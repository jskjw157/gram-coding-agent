# Typed Windows workspace worker (development)

This fixed native worker implements bounded list/stat/read, file write, file/directory move, recoverable trash/restore and mkdir. It accepts one bounded JSON request on stdin and returns one JSON result. There is no executable, shell, argument, environment, network or elevation operation. Roots and controller exclusions belong to trusted agent configuration, never remote MCP inputs.

Root and ancestor directory handles deny delete sharing. Components are opened relative to those handles and reject reparse points, hardlinks, ADS, traversal and Windows device aliases. Reads are limited to 1 MiB. Native read replies contain internal base64 bytes: the controller must screen complete content before any remote preview. The process closes after each operation and has a five-second watchdog so killing a WSL relay does not leave a native writer running indefinitely.

Writes compare the complete expected preimage while holding a transactional writer and commit atomically. Native TxF is deliberately capability-dependent: unsupported volumes fail closed. Microsoft [discourages new general dependencies on TxF](https://learn.microsoft.com/en-us/windows/win32/fileio/deprecation-of-txf); this is an explicit compatibility/review risk, not a promise of support on every Windows filesystem or future Windows version. The controller must advertise measured capabilities and never silently substitute unrestricted Node writes. [TxF isolation semantics](https://learn.microsoft.com/en-us/windows/win32/fileio/txf-basic-concepts) document writer conflicts. The actual host probe confirmed nontransactional writers are denied while the transaction is open.

An alternative `StorageStreamTransaction` probe was rejected here: an external file rename succeeded during its open transaction, and commit failed with FILE_NOT_FOUND. It does not establish the required pathname/version guarantee by itself. Existing Landlock on this WSL host rejects positive DrvFs operations; no M5 isolation setting was relaxed to accommodate Windows files.

Build with `scripts\build-windows-workspace-helper.cmd <output.exe>`, then run `python tests\security\windows-workspace-native.test.py <output.exe>`. These are actual harmless Windows fixture operations, not mocked security checks. The Windows CI job runs them explicitly. Install provenance, controller exclusions, durable authenticated recovery records, native owner consent, facade integration and external ChatGPT acceptance remain deployment gates.


Directory and recovery protocol fields are internal trusted-controller inputs. All requests retain `root`, relative `path`, `protectedPaths` and optional `protectedMutationPaths`. The controller must never accept roots, exclusions, recovery vaults or native operation fields directly from MCP input.

| Operation | Additional fields and result |
| --- | --- |
| `treeStat` | Non-root directory `path`; returns `rootIdentity`, `kind: "directory"`, `identity`, and `version` (internal SHA-256 observed manifest). |
| `move` directory | `destination`, `expectedRootIdentity`, `expectedFileIdentity`, `expectedKind: "directory"`, `expectedVersion`. |
| `trash` / `restore` | `expectedRootIdentity`, `expectedFileIdentity`, `expectedKind`, `recoveryRoot`, `recoveryId`, `expectedRecoveryRootIdentity`; directories use `expectedVersion`, files use complete `expectedBase64`. `path` is the ordinary source for trash and ordinary destination for restore. |

A manifest hashes names, kinds, identities and complete file contents, including hidden and binary files and empty directories. Its bounds are 10,000 total entries, depth 60 and 64 MiB aggregate contents. Larger or unsupported trees fail closed. Every observed descendant rejects reparse points and multiply linked files; protected paths and their ancestors cannot move. Internal manifest digests must be wrapped in an opaque controller version before remote exposure.

Directory versions describe the observed tree, not a kernel compare-and-swap against all concurrent child changes. Windows disallows renaming a directory while its descendant handles remain open. The worker validates and pins the bounded observed tree, closes those descendant handles, then renames through its still-open identity-checked transactional source handle. All root and source/destination ancestor handles remain pinned. A concurrent membership change in that final window can be included in the moved tree. The rename preserves the actual complete tree, never follows or copies new descendants, never replaces a destination, and never permanently deletes contents. [Microsoft documents that directory enumeration itself does not isolate nontransactional additions](https://learn.microsoft.com/en-us/windows/win32/fileio/programming-considerations-for-transacted-fileio-#directory-enumeration). Do not advertise atomic whole-tree version enforcement.

Recovery moves are same-volume native transactional renames, with no copy/delete fallback. `recoveryId` is one validated relative segment generated by the trusted controller. The exact vault root must already exist, be hidden, be covered by configured read protection, and have a protected DACL with allow ACEs limited to the current Windows user, SYSTEM and Administrators. Broad or inherited ACLs fail closed. The helper provisions no ACLs and exposes no ACL-editing or permanent-delete operation. For internal recovery only, protection ancestors of that exact pinned vault root are exempted; separately protected descendants remain denied. Ordinary list/read/stat/mutation requests continue to deny the vault and its contents, including through drive aliases.

The controller owns an authenticated durable recovery descriptor binding the ordinary root and item identity, vault identity, recovery ID, kind, observed version and intended restore destination. Restore validates those native identities/preimages and fails without clobbering a later writer. Success/denial responses contain no recovered bytes; file preimages retain the 1 MiB protocol limit. `DENIED_NO_CHANGE` proves native rollback, while `OUTCOME_UNKNOWN` requires controller reconciliation. Neither result authorizes an automatic destructive retry.
