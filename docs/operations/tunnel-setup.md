# OpenAI Secure MCP Tunnel setup

This project uses OpenAI `tunnel-client` as the **only** ChatGPT-to-local MCP tunnel. The local MCP server remains bound to `127.0.0.1:3847` and requires the `X-Gram-Agent-Auth` internal header.

## Credential split

Use three runtime references only:

- `CONTROL_PLANE_TUNNEL_ID`: the existing OpenAI tunnel ID.
- `CONTROL_PLANE_API_KEY`: a **Restricted** Runtime API key with **Tunnels Read + Use**.
- `GRAM_MCP_INTERNAL_SECRET_FILE`: path to the local file generated by `scripts/bootstrap-wsl.sh`.

An OpenAI Admin API key is only for tunnel management/CRUD. It must never be installed in the long-lived Gram runtime, systemd unit, tunnel config, or runtime environment file.

## Prerequisites

Inside WSL2:

1. systemd is enabled and is PID 1.
2. Node.js 24 and pnpm are installed.
3. the repository has been installed and built with `pnpm install --frozen-lockfile && pnpm build`.
4. the official `tunnel-client` binary is installed on `PATH`.
5. run the bootstrap as the dedicated non-root Linux account that will own the runtime.

## Bootstrap local state and units

From the repository root:

```bash
bash scripts/bootstrap-wsl.sh
```

The script is intentionally credential-preserving and idempotent for M1:

- creates `~/.gram-agent`;
- creates `~/.config/gram-coding-agent/secrets` with mode `0700`;
- generates `mcp-internal-secret` once and keeps it at mode `0600`;
- renders `/etc/gram-coding-agent/tunnel-client.yaml` with a file-backed MCP auth header;
- creates `/etc/gram-coding-agent/tunnel-runtime.env` only when it does not already exist;
- installs both systemd units and reloads systemd;
- does **not** provision a tunnel-management credential and does not overwrite an existing runtime key.

## Install the runtime tunnel references

Edit the root-owned file:

```bash
sudoedit /etc/gram-coding-agent/tunnel-runtime.env
```

Populate the two empty values while preserving the generated `GRAM_MCP_INTERNAL_SECRET_FILE` path:

```text
CONTROL_PLANE_TUNNEL_ID=tunnel_...
CONTROL_PLANE_API_KEY=sk-...
GRAM_MCP_INTERNAL_SECRET_FILE=/home/<runtime-user>/.config/gram-coding-agent/secrets/mcp-internal-secret
```

The runtime API key must be Restricted with Tunnels Read + Use. Do not substitute a tunnel administration key.

## Preflight with the official client

Do not enable the tunnel service until the official client preflight succeeds. Load the root-owned environment file only inside a privileged shell so the key is not placed on the command line:

```bash
sudo bash -c 'set -a; . /etc/gram-coding-agent/tunnel-runtime.env; set +a; tunnel-client --version; tunnel-client doctor --config /etc/gram-coding-agent/tunnel-client.yaml --explain'
```

Expected: configuration parsing succeeds, the local MCP endpoint is reachable, and the tunnel/runtime credential is accepted.

## Enable and start services

Start the agent first, then the tunnel:

```bash
sudo systemctl enable --now gram-coding-agent.service
curl -fsS http://127.0.0.1:3847/healthz
sudo systemctl enable --now openai-mcp-tunnel.service
```

Verify:

```bash
systemctl status gram-coding-agent.service
systemctl status openai-mcp-tunnel.service
```

The checked-in tunnel config uses the official YAML v1 schema, supplies the control-plane API key through `env:CONTROL_PLANE_API_KEY`, uses the `CONTROL_PLANE_TUNNEL_ID` environment variable for the tunnel identity, targets `http://127.0.0.1:3847/mcp`, and loads `X-Gram-Agent-Auth` from a `file:` secret reference.

## Failure handling

If the agent is unhealthy, stop the tunnel before debugging the agent:

```bash
sudo systemctl stop openai-mcp-tunnel.service
sudo journalctl -u gram-coding-agent.service -n 200 --no-pager
```

If `tunnel-client doctor --explain` fails, do not rotate the local MCP secret automatically. Fix the reported tunnel ID, runtime permission, network, or MCP reachability problem and rerun doctor.
